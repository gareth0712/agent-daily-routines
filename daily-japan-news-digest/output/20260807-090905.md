來源：Zenn - Claude Code｜發布：2026-08-06 10:58 JST

⚠️ 重要教訓：作者的自動化檢查 hook 靜默失敗長達 2 天，期間沒有任何 error output。根本原因是 hook script 遇到特定條件時完全靜默退出，繞過了所有錯誤通道。關鍵洞見：不能僅憑「沒有錯誤訊息」來確認 hook 正在執行，必須透過外部可觀察性（檔案時間戳記、外部 log、獨立監控）驗證。此案例完美呼應 Zero-Trust Observability 原則：不相信 agent 的自我報告。建議所有 hook 都加入顯式的「心跳」log，讓外部系統可獨立驗證 hook 存活狀態。

*【並行開發】放棄 isolation: worktree——將決定論與認知分開，與 AI 協作*
來源：Zenn - Claude Code｜發布：2026-08-06 09:18 JST

文章宣布放棄 Claude Code 的 `isolation: "worktree"` 用於並行開發，改採確定性 shell script 分配方式。放棄理由：worktree 每個 agent 需要約 200-500ms 的設定開銷，且無法完全防止所有衝突。新方案：透過確定性的任務分配腳本，在檔案/模組層級明確區隔各 agent 的操作範圍。核心概念是將「決定論」（agents 操作哪些檔案）與「認知」（agents 如何思考）分開設計。特別適合正在大量使用並行 Claude Code agent 的工程團隊。
