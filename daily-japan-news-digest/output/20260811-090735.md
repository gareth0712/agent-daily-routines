### [プロンプト・コンテキスト・ハーネス・ループ: Claude Code に大きなタスクを任せる設計](https://zenn.dev/mosida/articles/claude-code-large-task-design)
*提示詞・上下文・Harness・Loop：將大型任務委派給 Claude Code 的設計方法*
來源：Zenn - Claude Code｜發布：2026-08-10 23:15 JST

本文提出一套四層設計框架，用以確保 Claude Code 可靠地完成大型任務，層次由小到大依序為：**Prompt（提示詞）→ Context（上下文）→ Harness（執行環境）→ Loop（迴圈）**。Prompt 層要求明確記載任務對象、約束條件與完成判定條件，超大任務須切分為多段指令；Context 層的核心概念是「Context Rot（上下文腐敗）」，透過 `/clear` 指令定期重置，並以 `/compact`（壓縮摘要）、`/memory` 管理記憶體，僅在必要時引入最小化資訊。Harness 層將驗證邏輯置於 hooks 中以 exit code 強制執行，並以權限規則、沙箱、容器組成多層防禦；Loop 層則將狀態記錄於上下文之外的檔案，每次迭代僅推進一個任務單位。文章強調「/insights」指令可用於分析對話歷史，並建議遵循「若需兩次修正，就培育進 settings」的設定漸進原則。

本文系統性介紹 Claude Code 四個上下文管理指令的用途與時機：**`/context`** 即時視覺化目前 token 消耗量；**`/compact [focus hint]`** 在保留對話脈絡的前提下壓縮摘要，可附加焦點提示保留關鍵細節；**`/clear`** 執行完整重置，可命名本次 session 供之後以 `/resume` 召回；**`/autocompact "500k"`** 設定自動壓縮的閾值觸發點。實戰建議在每次「階段切換」（如從設計切換到實作）、debug 開始前、或 token 使用超過 70% 時主動觸發壓縮，可顯著降低上下文品質劣化的風險。
