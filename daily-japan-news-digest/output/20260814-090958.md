作者透過實驗證明，寫入 CLAUDE.md 的文字規則只能「機率性」地約束 Claude Code 的行為，而非決定性的強制限制。文章記錄了 68 個「罠（trap）」被觸發的案例，分析顯示規則字數與遵守率之間存在反向關係——規則越多反而容易造成重要規則被稀釋忽略。⚠️ 關鍵結論：不應依賴純文字規則防止高風險操作，必須輔以機構性防禦（mechanical defense）。作者提出「三層防御」架構：第一層為 CLAUDE.md 文字規則（機率性）、第二層為 settings.json 的 denyRules（部分有效）、第三層為 PreToolUse hooks 的程式碼攔截（決定性）。建議所有生產環境的 Claude Code 部署必須同時實作三層防禦。
