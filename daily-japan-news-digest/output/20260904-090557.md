本文以 Claude Code v2.1.248 實測驗證：當 symlink 作為 Grep/Glob 工具的直接路徑參數時，`permissions.deny` 規則（如 `"Read(./secret-dir/**)"` ）可正確攔截存取，事件流中出現 `permission_denied` 及 `is_error: true`。作者使用 `--output-format stream-json` 比較有無 deny 規則的原始事件流，排除依賴模型自我報告的干擾。測試範圍**僅涵蓋「symlink 作為直接參數」**，遞歸遍歷途中遇到的 symlink、glob 模式中的 symlink 及 TOCTOU 情境尚未測試，可能有不同的安全風險。已部署 `permissions.deny` 的組織在此常見場景下無需重新配置，現有保護仍然生效。

### [PreCompact hookがClaudeの動作を変えない理由](https://zenn.dev/joemike/articles/cc-compact-persona-loss-2026)
*PreCompact Hook 為何不改變 Claude 的行為——以及哪種 Hook 才真正有效*
來源：Zenn - Claude Code｜發布：2026-09-04 02:28 JST

作者區分兩種 PreCompact hook 架構：**備份型 hook**（複製檔案）僅保存對話記錄供人工檢閱，其 stdout 輸出對 Claude 的壓縮流程不可見，不影響後續行為；**規則注入型 hook**（stdout 輸出）才能將關鍵約束嵌入壓縮摘要，真正影響 Claude 的決策連續性。核心發現：CLAUDE.md 系統提示在壓縮後仍保留，真正丟失的是對話中形成的優先順序共識（如「本任務 A 優先於 B」）。解決方案是建立 `active-rules.md` 存放 3–5 條關鍵約束，由 PreCompact hook 輸出至 stdout，Claude 即可在壓縮摘要中保留這些規則，跨 session 維持一致性。兩種 hook 可同時配置於陣列中，各自解決人工恢復與 Claude 運行連續性兩個不同問題。
