### [iPhone から Tailscale 経由で Mac の Claude Code を操作する](https://zenn.dev/yoshihiko555/articles/fc64747e00c45e)
*透過 Tailscale VPN 從 iPhone 遙控 Mac 上的 Claude Code*
來源：Zenn - Claude Code｜發布：2026-09-08 09:04 JST

Tailscale 搭配 SSH 實現跨裝置接續作業，重點在於「加入已在跑的 tmux session，而非重新開新的」。設定分三步：(1) 雙裝置同帳號登入 Tailscale 取得 100.x.x.x 私有 IP；(2) Mac 的 SSH 設定只接受 Tailscale IP 的連線，強制使用金鑰驗證；(3) iOS 端使用 Prompt 3 app 產生裝置金鑰，以 `tmux attach` 接入既有 session。安全設計上，因 macOS launchd 限制無法直接限定 listen 位址，改採拒絕非 Tailscale 流量的方式。日文輸入在 Prompt 3 上表現穩定，是同類方案中少見的痛點解決案例。這套架構不需固定 IP 或 Port Forwarding，適合在外也需持續跑 agent 任務的開發者。

### [AIレビューが細かすぎて使えない人へ。公式プロンプトにあった「報告させない」の1行](https://zenn.dev/tmasuyama1114/articles/ai_review_what_not_to_report)
*給覺得 AI Code Review 雜訊太多的人——官方 Prompt 中那句「不要報告」*
來源：Zenn - Claude Code｜發布：2026-09-08 06:30 JST

OpenAI 和 Anthropic 的官方 code review prompt 有兩種截然不同的做法：OpenAI 採「前置過濾」，在 prompt 中明訂排除樣式回饋、命名意見、低價值清理、無根據的猜測；Anthropic 採「後置過濾」，先生成完整發現，再刪除信心度低於 80% 的項目。「報告させない」手法的核心是在分析開始前先聲明排除範圍——既有 bug、lint/type checker 能處理的問題、未修改行的問題、無根據的疑慮。兩種官方實作共同原則是：只報告重要問題（不含風格偏好）、一個嚴重發現優於多個弱發現、所有發現必須有 codebase 中的具體依據。⚠️ 實作建議：在自定義 review 指令中加入「不回報這些項目」的明確清單，比只說「要嚴格」更有效。
