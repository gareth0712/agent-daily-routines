### [Claude Code の PreToolUse hook で危険コマンドを実行前にブロックする実装 — permissionDecision の返し方と matcher の3つのハマりどころ【2026】](https://qiita.com/yureki_lab/items/e7ef0d6efbd7a9b73442)
*用 Claude Code 的 PreToolUse hook 在危險指令執行前先擋下來——permissionDecision 的回傳寫法，以及 matcher 的三個踩雷點【2026】*
來源：Qiita - ClaudeCode｜發布：2026-09-15 08:02 JST

本篇針對 Claude Code v2.x，說明如何用 `PreToolUse` hook 在危險指令真正執行前攔截。設定方式是在 `~/.claude/settings.json` 的 `hooks.PreToolUse` 底下註冊一筆 `{"matcher": "Bash", "hooks": [{"type": "command", "command": "python3 ~/.claude/hooks/guard.py"}]}`，讓 Claude Code 在每次呼叫 `Bash` 工具前先執行這支 Python guard script；script 從 stdin 讀進 JSON，檢查其中的 `tool_input.command`，並把判斷結果以 JSON 印到 stdout，格式為 `{"hookSpecificOutput": {"hookEventName": "PreToolUse", "permissionDecision": "deny", "permissionDecisionReason": "..."}}`，`permissionDecision` 的合法值只有 `allow`、`deny`、`ask` 三種。文章列出三個容易踩的坑：第一，`matcher` 只對工具名稱（如 `Bash`、`Edit`）生效，不會比對指令字串本身，要擋特定危險指令必須靠 script 內部邏輯自行解析 `tool_input.command`；第二，`permissionDecision` 必須巢狀在 `hookSpecificOutput` 底下，⚠️ 格式錯誤時 hook 會靜默失敗、不會噴錯，等於危險指令照樣被放行卻毫無警訊，屬於安全性上最容易被忽略的陷阱；第三，`settings.json` 的變更不會套用到正在執行中的 session，必須開新 session 才會生效。整體來說這是一份可直接照抄的 hook 防護實作範本，尤其適合長時間授權 Claude Code 自主操作 shell 的場景。
