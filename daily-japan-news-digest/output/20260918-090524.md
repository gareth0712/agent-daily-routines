### [未コミットの変更が消える：並行セッションとgit addの空振り](https://qiita.com/miyoki_labs/items/b10571c12398a9678c93)
*未提交的變更憑空消失：並行 session 與 git add 撲空的陷阱*
來源：Qiita - ClaudeCode｜發布：2026-09-18 07:20 JST

作者在同一個 repo 上同時開了多個 AI 代理 session 作業，先在一個 Markdown 檔追加一則筆記後就切去做別的事，事後想找回那則筆記時卻發現「憑空消失」，重寫後執行 commit 也顯示成功，但打開一看內容根本是空的。追查後發現第一起事故是另一個並行 session 執行了「巻き戻し系」指令（如 `git reset --hard`、`git checkout -- <file>`）而悄悄丟棄了未提交的變更；第二起事故則是在「寫入內容」與「執行 `git add`」之間，另一個 session 把工作目錄還原了，導致 `git add` 對照到的其實是已還原、沒有變更的檔案，因偵測不到差異而「靜默成功」，形成看似正常卻是空的 commit。作者點出核心問題是「寫進檔案 ≠ 保留在 Git 中」，`git reset --hard`、`git checkout -- <file>` 會靜默丟棄未提交變更，相對地 `git merge`、`git pull`、`git checkout <branch>` 則會在可能覆蓋時中止並報錯，而 `git add` 找不到差異時完全不會報錯，使問題難以察覺。解法是縮短「寫入→add→commit→push」之間的時間差、把四個動作串成單一連續流程，並改用 `git show HEAD:<檔名>` 直接檢查已提交內容而非只看工作目錄，把「未提交等於沒有真正記錄」寫進作業規範中。
