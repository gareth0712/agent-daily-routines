### [Claude Code のヘッドレスモード(claude -p)を CI・シェルスクリプトから動かす実装手順 — stream-json が出ない・許可待ちで固まる・セッション再開の3つのハマりどころ【2026】](https://qiita.com/yureki_lab/items/a7dc953980b70942edf1)
*在CI與Shell腳本裡跑Claude Code無頭模式(claude -p)的實作重點：三個常見卡關點*
來源：Qiita - ClaudeCode｜發布：2026-09-19 08:02 JST

這是一篇實作導向的Qiita文章，講怎麼把`Claude Code`的headless模式(`claude -p`)接進CI與shell腳本，基本指令格式是`claude -p "<prompt>" --allowedTools "Read" --output-format json > result.json`，回傳單一JSON物件含result、session_id與費用資訊，適合用pipe處理。文章點出三個常踩的坑：第一，用`--output-format stream-json`時如果沒有加`--verbose`會直接靜默失敗，錯誤訊息其實寫著「When using --print, --output-format=stream-json requires --verbose」，兩個參數要一起用才能拿到帶type標記(system/assistant/user/result)的串流JSON。第二，headless模式沒有互動使用者可以授權，Claude呼叫未授權工具（例如Bash）時不會丟出錯誤，而是在result欄位裡靜默失敗、exit code仍是0，容易誤判為成功，解法是用`--allowedTools`做細粒度授權（例如`--allowedTools "Read,Grep,Glob,Bash(git diff *)"`），避免整包授權，也可以搭配`--permission-mode acceptEdits`處理寫入操作。第三，每次呼叫`claude -p`預設都會開新session、context會斷掉，解法是從前一次JSON結果取出`session_id`，下次呼叫用`--resume "$SID"`接續；文章也給了一個GitHub Actions實戰範例，用`--max-turns`與`--max-budget-usd`雙重限制避免CI中跑飛，並提到`--restricted`旗標可以在不信任的repo環境裡移除指令執行能力。
