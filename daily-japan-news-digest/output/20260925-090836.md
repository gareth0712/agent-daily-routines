### [Claude Code の permissions を settings.json に書いたのに効かない3つの理由 — deny が allow に勝つ・Write() は参照されない・先頭 / はルートではない【2026】](https://qiita.com/yureki_lab/items/6f9175d70d294840311c)
*Claude Code 的 permissions 寫進 settings.json 卻不生效的三個原因——deny 贏過 allow、Write() 不被參照、開頭的 / 不是根目錄【2026】*
來源：Qiita - ClaudeCode｜發布：2026-09-25 08:04 JST

文章解說 Claude Code v2.1.2xx 系列中，`settings.json` 的 `permissions` 設定語法正確卻不生效的三個實作層面原因。第一，規則評估順序固定為 deny → ask → allow，只要先命中範圍較廣的 `deny`，即使有更具體的 `allow` 規則也無法生效，作者建議 `deny` 一開始就設得夠窄、不留例外。第二，路徑規則參照有限制：`Write(docs/**)`、`Glob(src/**)`、`NotebookEdit()` 這類寫法雖然會被接受但實際不會被參照，必須分別改成 `Write()` → `Edit()`、`Glob()` → `Read()`、`NotebookEdit()` → `Edit()` 才有效。第三，路徑開頭的 `/` 並非代表檔案系統根目錄，而是以設定檔所在位置為錨點：`//path` 才是檔案系統絕對路徑、`~/path` 以家目錄為基準、單一 `/path` 則以設定檔所在處為基準。文章補充 Bash 權限規則只檢查 Claude 寫出的指令字串本身，因此可能被 `/bin/rm` 或 `bash -c` 這類寫法繞過，若需要真正的邊界強制執行，建議搭配沙箱或 hook。
