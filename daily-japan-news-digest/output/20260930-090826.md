來源：Qiita - ClaudeCode｜發布：2026-09-30 08:45 JST

作者整理讓 Claude Code 寫 Playwright 腳本時的 4 個陷阱。第一是 session 管理：`page.context().storageState()` 可一併保存登入狀態，但 `httpOnly` cookie 無法從 JavaScript 取得，且行為會隨 Playwright 版本而異，檔案放哪、何時更新需自行設計。第二是 headless 預設值會被部分服務偵測，可改用 `chromium.launch({ headless: false })`；遇到 Google OAuth、CAPTCHA 或 X 這類強防護平台時，較務實的做法是人工登入一次再重用 session，作者刻意不走規避 bot 偵測的路線。第三是選擇器應優先用 `data-testid`、`aria-label`，其次文字內容與 `placeholder`，`class` 與 `id` 為最後手段，因為 Claude Code 依截圖推測的選擇器會隨介面改版失效。第四是錯誤處理要寫入日誌並以 `process.exit(1)` 回傳終止碼，讓排程器能偵測失敗；作者本業使用 Copilot Studio 與 Power Automate，認為問題結構相似。
