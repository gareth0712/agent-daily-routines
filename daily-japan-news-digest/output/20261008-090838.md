*無人長時間執行 AI agent 時不弄壞狀態檔的 Python 實作：JSONDecodeError、os.replace 跨裝置連結、PID 檔鎖殘留三個陷阱*
來源：Qiita - ClaudeCode｜發布：2026-10-08 08:01 JST

文章針對以 cron 或迴圈長時間無人執行 Claude Code 等 agent 時的三個狀態檔問題提供對策。第一，`open(path, "w")` 會先清空檔案，寫到一半被終止會留下截斷檔而引發 `JSONDecodeError`；解法是在同目錄寫暫存檔、`fsync` 後用 `os.replace` 覆蓋，且不可吞掉解析錯誤用空清單重跑。第二，`tempfile.mkstemp()` 未指定 `dir` 時暫存檔在 `/tmp`，跨磁碟時 `os.replace` 會出現 `OSError: [Errno 18]`，需設 `dir=path.parent`。第三，PID 檔只在正常結束時刪除，`kill -9` 後會殘留並使 agent 無法啟動，且 PID 重用會造成誤判；改用 `fcntl.flock`，行程結束時由 OS 釋放鎖，但鎖檔應放本機磁碟，網路檔案系統上可能不可靠。
