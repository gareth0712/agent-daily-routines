本文依官方 release note 整理 v2.1.304（日本時間 10 月 20 日早晨發布）的三項變更。第一，mod 的 `tool.check` 新增 `decider: "person"` 指定，此類請求必須經許可對話框或 host callback 由人核准，在無人可確認的環境會附理由直接拒絕；同一事件也新增 `e.isReadOnly`，可標示工具呼叫是否唯讀，方便自製 mod 區分讀取、寫入與必須人工判斷的操作。第二，compaction 之後會重新送出 Skill 清單，而 `/reload-skills` 只會送出新增或變更的 Skill，對長時間開發與邊改邊用自製 Skill 的情境有幫助。第三，Pro / Max 方案在續用久未使用的對話時，若會明顯影響 5 小時用量額度，會出現警告並可選擇繼續或開新對話。作者強調這並非「既有處理自動改為必須人工核准」，也不代表用量或費用一律下降，且本文只是整理 release note，並非實測心得。
