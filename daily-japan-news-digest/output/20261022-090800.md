### [marketplace と plugin.json、どちらが勝つかは項目で決まる](https://note.com/aibuild_015/n/n07b3036111b0)
*marketplace 與 plugin.json 衝突時誰優先，取決於欄位*
來源：note - #ClaudeCode｜發布：2026-10-22 09:00 JST

整理 Claude Code plugin 系統中 `marketplace.json` 與 `plugin.json` 同名欄位衝突時的優先規則（依 2026-10-11 確認的官方「Plugin manifest reference」「Plugin marketplace reference」）。`version` 以 `plugin.json` 為準，相對路徑外掛若不一致，`claude plugin validate` 會警告「At install time, plugin.json wins」；`defaultEnabled` 以 marketplace 為準，且使用者的 `enabledPlugins` 一旦寫入值，之後外掛更新也不會覆蓋；`displayName`／`description`／`author` 等顯示欄位 marketplace 有寫就用 marketplace。`name` 不一致時兩邊都會用到：`enabledPlugins` 用 marketplace 名稱、元件名前綴用 `plugin.json` 名稱。`commands`／`agents`／`skills`／`hooks`／`outputStyles`／`themes` 六類元件依 `strict` 決定：`strict: true`（預設）以 `plugin.json` 為主並把 marketplace 的元件加上去（`hooks` 同事件 matcher 則被 marketplace 取代）；⚠️ `strict: false` 時 marketplace 只要寫了任一元件欄位就會因「has conflicting manifests」而無法載入。另外若有 `plugin.json`，marketplace 上的 `mcpServers`／`lspServers`／`userConfig`／`channels` 會被忽略，必須寫在 `plugin.json`。
