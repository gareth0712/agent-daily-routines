### [Claude Codeの Invalid permission rule was skipped を実測: 書式ミスのdenyは効かない](https://zenn.dev/yorusuzu/articles/claude-code-invalid-permission-rule-skipped)
*實測 Claude Code 的 Invalid permission rule was skipped：格式錯誤的 deny 不會生效*
來源：Zenn - Claude Code｜發布：2026-10-28 01:24 JST

以 Claude Code 2.1.296 與 Haiku 實測：`claude -p` 加上 `--json-schema` 時，結構化輸出是 AI 呼叫 `StructuredOutput` 工具產生，若提示與 schema 衝突（例如要求 severity 為 critical 但 enum 沒有該值），AI 試 1～2 次後可能直接用文字回答「無法輸出」。⚠️ 此時仍是 exit 0、`subtype: "success"`、`is_error: false`，只是缺少 `structured_output` 鍵；只有達到重試上限（預設 5 次，環境變數 `MAX_STRUCTURED_OUTPUT_RETRIES`）才會是 `subtype: "error_max_structured_output_retries"` 與 exit 1，故意違反的 33 次執行中只有 1 次 exit 1，其餘失敗全是放棄後 exit 0。正確判定是 `subtype == "success"` 且 `structured_output` 有值，有值就是已通過驗證，不必再自行驗 enum 或型別。Python 範例使用 `--output-format json`、`--setting-sources ""`、`--tools ""`，並提到 Windows 注意事項；若在提示中明寫指示與 schema 可能衝突，enum 的情況 3 次都會被 AI 修正，可減少放棄。
