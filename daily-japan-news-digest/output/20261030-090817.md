### [Claude Code で "API Error: Stream idle timeout - partial response received" が出たときの直し方（CLAUDE_STREAM_IDLE_TIMEOUT_MS と長い出力の分割）](https://qiita.com/homhom44/items/34211c5b1960ace4aa0c)
*Claude Code 出現 "API Error: Stream idle timeout - partial response received" 時的修法（CLAUDE_STREAM_IDLE_TIMEOUT_MS 與拆分長輸出）*
來源：Qiita - ClaudeCode｜發布：2026-10-30 06:31 JST

此錯誤源自 Claude Code 內建的 stream watchdog 在一段時間沒收到資料後中斷串流，常見於模型長時間思考或寫入大檔案；完全沒收到資料時訊息則為 "no chunks received"。修法：在 `~/.claude/settings.json` 的 `env` 加入 `CLAUDE_STREAM_IDLE_TIMEOUT_MS=600000`（10 分鐘）並重啟；若自行設過 `CLAUDE_ENABLE_STREAM_WATCHDOG=1` 應移除；另可用 `CLAUDE_BYTE_STREAM_IDLE_TIMEOUT_MS`（10 秒至 30 分鐘，優先於前者）分開調整 byte-level 計時器。官方預設為 event-level 300 秒、byte-level 直連 180 秒／經閘道 300 秒，低於 5 分鐘的設定值會被提高到 5 分鐘。把長計畫或大檔案拆成多次請求是作者與使用者的經驗，並非官方建議。確認版本為 Claude Code 2.1.312；GitHub issue #46987、#47698 當時仍為 open，作者未實際重現，v2.1.104 之後部分資料已送達時不再自動切換為非串流模式。
