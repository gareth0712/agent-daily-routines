### [Claude Code で "Self-signed certificate detected" / "SSL certificate verification failed" が出たときの直し方（社内プロキシと NODE_EXTRA_CA_CERTS）](https://qiita.com/homhom44/items/922d0458086bf4df7d0d)
*Claude Code 出現 "Self-signed certificate detected" / "SSL certificate verification failed" 時的修法（公司內部 proxy 與 `NODE_EXTRA_CA_CERTS`）*
來源：Qiita - ClaudeCode｜發布：2026-11-06 09:05 JST

原因是公司 proxy 或資安設備對 HTTPS 做 TLS 檢查並以自家 CA 重新簽章，而 Claude Code 使用自己的信任清單，因此拒絕該 CA；瀏覽器能正常是因為 IT 已把 CA 裝進公司電腦。修法是向 IT 取得 PEM 格式的根 CA（含中繼憑證的 bundle 更佳），設定 `export NODE_EXTRA_CA_CERTS=/path/to/corp-ca.pem` 後啟動 `claude`（Windows 用 `$env:NODE_EXTRA_CA_CERTS`），可寫進 `~/.zshrc`。`NODE_TLS_REJECT_UNAUTHORIZED=0` 會完全關閉驗證而不建議；需經 proxy 連外時另設 `HTTPS_PROXY`；路徑打錯會出現 `Ignoring extra certs` 警告。作者在 Claude Code 2.1.318（macOS 26.6）以本機假 CA 重現並驗證修法有效，並指出 v2.1.273 之前的錯誤訊息沒有 `NODE_EXTRA_CA_CERTS` 提示，登入時的訊息還會建議執行 `claude doctor`。`CLAUDE_CODE_CERT_STORE`、`NODE_USE_SYSTEM_CA` 在 2.1.316 的 binary 中可見但未在官方文件確認，且有 issue（#69387）回報失效；Zscaler 等實際企業 proxy 未驗證。文中未提及 breaking change 與競品。
