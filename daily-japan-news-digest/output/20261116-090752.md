*不讓多個 AI agent 搶同一件工作：把 git push 當作「開工記號」的兩個陷阱*
來源：Qiita - ClaudeCode｜發布：2026-11-16 08:56 JST

作者並行運行多個 Claude Code 工作階段，每 30 分鐘喚醒一次，從共用 repo 的 `dispatch/` 資料夾領取委託檔，並用遠端 git 分支 `claim/<job>` 當作免伺服器、免資料庫的互斥鎖。陷阱一：兩個 agent 都 push 同一個 `origin/main` commit 時，第二個得到「Everything up-to-date」且 exit code 為 0，連 `--force-with-lease=<ref>:` 也擋不住。陷阱二：refspec 加 `+` 會強制覆蓋既有分支並無視 lease 條件，先搶到的記號被抹掉。解法是每個 agent 用 `git commit-tree` 建立專屬 commit（parent 為 `origin/main`，訊息含 agent 名稱與時間），不加 `+` 推送，第二個會被 non-fast-forward 拒絕（rc=1）；作者在 git 2.43 驗證。另可用 `git ls-remote --heads origin 'claim/*'` 列出進行中的工作，過舊的記號視為 agent 中途掛掉。
