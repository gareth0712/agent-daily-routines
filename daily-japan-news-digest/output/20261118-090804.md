### [AIエージェントにテストを足させる条件を規約に書く ─ 足さない変更の線引きと、減らすときに残すテスト](https://qiita.com/itaraiguma/items/f1c47c4269609481d80e)
*把「允許 AI agent 新增測試的條件」寫進規約：不加測試的變更界線，以及縮減測試時該留哪些*
來源：Qiita - ClaudeCode｜發布：2026-11-18 08:38 JST

作者發現 agent 每次變更都加測試，測試只增不減，拖慢 CI 並讓 agent 讀的檔案變大。第一步用 `git log origin/main --since=2026-11-01 --no-merges --numstat --format= -- tests/` 搭配 awk 統計增刪行，其環境 17 天內有 170 個 commit 動到測試、新增約 3 萬行卻只刪 121 行。第二步在 `CLAUDE.md` / `AGENTS.md` 明列「可以加測試的情況」（修 bug 的 regression 測試原則 1 件、會影響發布或品質判定的判定邏輯），並點名不加的變更（效能改善、hook/CI 配線、log 文案、CLI 參數、一次性 script、文件），每次變更以 1～3 件為目安。注意「實作與測試放同一 commit」「不要改測試」這類既有規則可能反而推動或阻礙縮減，Skill 內的「新增測試」步驟也要同步修改。縮減時保留守護判定結果與 fail-safe 的測試，移除只驗證快取命中、CLI 傳參等配線與效能性質的測試。

### [claude.aiのサインイン切れを夜間ジョブの前に検知する — claude -p を止めないための監視スクリプト](https://qiita.com/joinclass/items/9b302cc1dafef6a69f5f)
*在夜間 job 之前偵測 claude.ai 登入失效：不讓 `claude -p` 停擺的監控 script*
來源：Qiita - ClaudeCode｜發布：2026-11-18 08:30 JST

作者以 macOS + launchd 跑十多支無人值守的 `claude -p` 排程，指出登入失效時 `claude -p` 會靜默失敗（輸出 Not logged in），若 wrapper 寫法不當甚至回傳 rc=0。第一個坑是 pipe：因 `claude --output-format json ... | python3 record-cost.py` 的終止碼取自最後一個指令，必須在 pipe 後立刻用 `PIPESTATUS` 取 claude 側的值（2026-11-11 發現並修正）。⚠️ 第二個坑：加 `--bare` 想加速啟動，會因為不載入設定與認證而在已登入狀態仍出現 Not logged in，故不適用 claude.ai 訂閱登入的運用。解法是夜間 job 前先跑一次 `claude -p "OKとだけ返して" --max-turns 1`（含 timeout 120），比對 `Not logged in|Invalid API key|OAuth token has expired|Please run /login|401`，失敗就通知 Slack（6 小時內不重複）並放標記檔讓後續 job 略過；wrapper 另用 `--no-session-persistence` 與 `--max-budget-usd 3`。cron 亦可套用。
